# **Issue**

The N6 (STM32N6570-DK Discovery kit) SPI occasionally hangs on reads. This can be observed to occur after running the below test code snippet for 10-900 seconds (based on testing with two disco kits). It happens even when nothing is connected to the SPI bus.

The issue occurs because the RXP flag (to signal data has been received) is never raised (I'm unsure why), and the driver code waits in an infinite loop for it. The call tree is:
- [blocking_read](https://github.com/embassy-rs/embassy/blob/3651d8ef249dc20d30df7382237f2451d889c011/embassy-stm32/src/spi/mod.rs#L596)
   - [transfer_word](https://github.com/embassy-rs/embassy/blob/3651d8ef249dc20d30df7382237f2451d889c011/embassy-stm32/src/spi/mod.rs#L1393)
      - [spin_until_rx_ready](https://github.com/embassy-rs/embassy/blob/3651d8ef249dc20d30df7382237f2451d889c011/embassy-stm32/src/spi/mod.rs#L1306)

### Steps performed by `blocking_read`

1. Disable SPI (clear CR1.SPE). The embassy documentation says this is needed to `avoid overrun causing the SPI RX state machine to get stuck...?`
2. Set the word size (CFG1.DSIZE = 0x7 (8-bit), skipped if already done)
3. Enable SPI (set CR1.SPE)
4. Flush RX FIFO (read RX data register until RXP is cleared)
5. Wait until we have room in the TX FIFO (SR.TXP flag set) (or TI frame format error, Mode Fault, CRC error, overrun)
6. Write zero to the TX data register
7. Master transfer start (set CR1.CSTART)
8. Wait until the RX FIFO has data (SR.RXP flag set) (or TI frame format error, Mode Fault, CRC error, overrun) <mark>[Trapped here, as the RXP flag is never set]</mark>
9. Read data from the RX data register

### Test code

The following code was used to trigger the issue. Effectively it spams the SPI with writes and reads. Note that SPI always sends data both ways simultaneously. A write is actually (send data, discard received) and a read is (send zero, receive data).

This code writes two randomly selected bytes followed by a read.

```Rust
let mut spi_config = spi::Config::default();
spi_config.frequency = Hertz(100_000);
let spi = spi::Spi::new_blocking(
  p.SPI5, // SPI
  p.PE15, // SCK
  p.PG2,  // MOSI
  p.PH8,  // MISO
  spi_config,
);
let mut chip_select = Output::new(p.PA3, Level::High, Speed::VeryHigh);
loop {
    let mut spi_buf = [33_u8; 1];
    info!("SPI Buffer: {}", spi_buf);
    chip_select.set_low();
    spi.write(&[0x03_u8, 0x2c_u8]);
    spi.read(&mut spi_buf);
    chip_select.set_high();
    info!("SPI Buffer: {}", spi_buf);
}
```

### RXP Flag (reference manual)

> The flag is changed by hardware. It monitors the total number of data currently available at RxFIFO if SPI is enabled. RXP value depends on the FIFO threshold (FTHLV[3:0]), data frame size (DSIZE[4:0] in SPI mode and DATLEN[1:0] in I2S/PCM mode), and actual communication flow. If the data packet is read by performing consecutive read operations from SPI_RXDR, RXP flag must be checked again once a complete data packet is read out from RxFIFO.
0: RxFIFO is empty or an incomplete data packet is received
1: RxFIFO contains at least one data packet
